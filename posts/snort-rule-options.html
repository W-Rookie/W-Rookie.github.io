Snort Rule 옵션
제대로 읽기

한 줄짜리 탐지 규칙을 헤더와 옵션으로 나누고, 자주 사용하는 네 가지 옵션의 역할을 살펴봅니다.

Snort 규칙은 크게 Rule Header와 Rule Options로 나뉩니다. 헤더는 어떤 트래픽을 볼지 정하고, 괄호 안 옵션은 그 트래픽에서 무엇을 검사하고 어떻게 기록할지 정합니다.

alert icmp any any -> any any (msg:"icmp-request"; itype:8; sid:1000000; rev:1;)

헤더부터 해석하기

alert는 조건이 일치하면 경보를 만들라는 동작입니다. icmp는 검사할 프로토콜이며, any any → any any는 출발지와 목적지 IP·포트를 제한하지 않는다는 의미입니다.

네 가지 핵심 옵션

옵션역할현재 규칙의 의미
msg경보에 표시할 메시지icmp-request로 기록
itypeICMP 메시지 유형8번 Echo Request 탐지
sid규칙을 식별하는 고유 번호사용자 규칙 1000000
rev규칙의 수정 버전첫 번째 버전

msg — 경보의 이름

msg는 패킷을 탐지했을 때 alert 로그나 SIEM 화면에 보이는 문구입니다. 분석자가 한눈에 이해할 수 있도록 공격 또는 행위를 구체적으로 작성하는 것이 좋습니다.

itype — ICMP 유형

itype:8은 ping 요청인 Echo Request, itype:0은 응답인 Echo Reply입니다. 같은 ICMP라도 목적에 따라 서로 다른 유형을 가집니다.

sid — 규칙의 주민번호

모든 규칙은 서로 다른 SID를 가져야 합니다. 사용자 정의 규칙은 기존 배포 규칙과 충돌하지 않도록 보통 1000000 이상의 번호를 사용합니다.

rev — 수정 이력

규칙 조건을 변경했다면 rev:1을 rev:2로 올립니다. SID는 그대로 유지하고 revision만 변경해야 같은 규칙의 새 버전임을 알 수 있습니다.

CHECK POINT

옵션은 세미콜론으로 구분하고 규칙 마지막에도 세미콜론을 붙입니다. 쉼표가 필요한 복합 옵션에서는 누락 여부도 확인해야 합니다.

설정 검사

규칙을 수정한 뒤에는 바로 실행하기 전에 설정 검사를 수행합니다. 인터페이스 이름은 실제 환경에 맞게 변경합니다.

snort -T -i eth1 -c /etc/snort/snort.conf

마지막에 Snort successfully validated the configuration!이 출력되면 문법 검사를 통과한 것입니다.
